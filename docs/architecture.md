# 架构与数据流

Hermit 使用 Wails v3：React 界面通过生成绑定调用 Go 服务。核心处理不依赖独立 Python / Node 运行时；系统集成仍会调用 macOS 工具和现有 Mihomo 校验命令。

| 目录 | 职责 |
| --- | --- |
| `frontend/src/` | 页面、编辑表单、状态与错误反馈、开发 mock |
| `frontend/bindings/` | Wails 生成的调用与类型，随 Go 服务更新 |
| `internal/app/` | 服务入口、串行操作、保存 / 自动应用 / 测试编排 |
| `internal/core/` | 存储、加密、Clash 控制、脚本组合、事务和出口检查 |
| `build/` | macOS 图标、元数据、构建和临时签名 |
| `scripts/` | 元数据、产物和发布准备检查 |

## 写入流程

`界面操作 → 服务互斥锁 → 存储锁 → 校验当前基线 → 组合脚本 → Mihomo 配置校验 → 加密事务日志 → 原子写入 → 重载 → 核验监听 → 完成`

失败尝试回滚；中断后的事务日志用于下次恢复。外部订阅、脚本或生成配置变化时拒绝覆盖。总开关关闭时保存映射不应用；保存并测试会启用并应用所有已启用映射。

## 数据边界

- Go 核心拥有本地状态和凭据，前端只获取公开状态和凭据是否存在。
- 状态文件可包含节点名和端口，不应作为公开诊断附件。
- 测试经指定 SOCKS5 端口发起 HTTPS 请求，并核对 Clash 捕获的连接链。可达与节点身份确认分开表示。
- macOS 数据目录、Bundle ID 和钥匙串命名保留历史兼容；Go 模块路径仅属于源码标识。

## 开发与生产隔离

开发浏览器使用 mock；打包窗口的 `wails:` 协议及原生系统标记用于识别 Wails。生产构建不允许回退 mock。自动测试覆盖环境识别，构建后检查示例数据未进入生产 bundle。

核心测试通过替换控制器、文件目录、进程发现和钥匙串 runner 隔离真实环境。仅覆盖数据目录的环境变量不能替代这些隔离措施。
